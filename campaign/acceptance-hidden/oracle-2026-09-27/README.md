# 仿隐藏意图评估器（09-27 夜，主会话专用）

用 09-24 旧题失败记录里的隐藏测试标题（`*-intents.json` 的 `hidden_intent_zh`）写的 Playwright 测试，跑法同官方运行器：一个不重置的后端、1 个 worker、每条 10 秒、按文件名顺序。只用于本地定位缺陷和比较候选包；不进包、不写进派发单（甲方 09-27 22:16 同意这种本地推测）。

- 跑一个应用：`./run.sh <套件目录名> <应用目录> <输出.json> <端口> [grep]`；套件目录名是 `github`、`github-polluted`、`sheet`，或分块目录 `sheet-A` 等。
- 合并分块并跑某题全部校准应用：`./run_all.sh <github|sheet> <并行数> <标签>`，合并结果写到 `<题>/tests`。
- 校准汇总：`python3 calib.py <题> <标签>`（总数对隐藏分、GitHub 两份逐条标签的一致率）。
- `apps/<题>-<隐藏分>-<runid>/`：30 份已知隐藏分的官方应用包。
- `github-polluted/`：在第 10 条后插一条 `12z-sim-reset-alice`（模拟隐藏套件改掉 alice-dev 的密码）。在污染模式下，评估器分数与隐藏分同一量级：32–40 对 20–25。
- 各分块的 `notes.md`（每条测试的意图与假设）和 `calibration.md`（各应用通过数、缺陷分类）是诊断正文。
- `research/`：论文笔记、GitHub 项目笔记、书面测试覆盖审计、flash 意图还原及评分。
- `diag/`：31 次正式 run 的修复统计（`runs.csv`），以及给主办方的问询稿。

已知局限：
- Sheet 在 81 分应用上约 98，比隐藏高约 17，差额未查明。
- GitHub 不模拟改密码时比隐藏高约 40；模拟后仍高约 12–15。
