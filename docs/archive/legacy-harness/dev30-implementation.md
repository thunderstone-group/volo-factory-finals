## 已实现

**截断后改变可执行动作。** 新建应用的整包模式和已有应用的紧凑补丁模式，首次出现 `length` 都立即退回普通文件/编辑工具；不执行残缺响应，不清空已写文件。连续三次截断停止该批次，并在 trace 留下模式切换与失败原因。正常完整响应重置连续计数。三次是保守的起始止损策略，不是已经测得的最优配置。

**自测与可信验证不再混名。** 本地构建/启动/检查仍可驱动修复与调度，但结果声明 `local_checks_only`、`requirements_verified=false`，任务结果改用 `self_checked_requirements`。`verified_requirements` 不再因为整批自测通过而自动填满，也不再给 SDK 发送逐需求 `mark_test_passed`。保留 `status=completed` 表示本地执行流程结束，不表示官方验收通过。该 SDK 事件变化尚未经过官方运行验证。

**新增执行器外评分入口。** `harness_lab/external_gate.py` 运行开发者提供、版本固定的外部检查，而不是候选工程自己的自测。检查目录、冻结候选和原始需求目录必须分离。需求、源码、验收脚本和解释器绑定哈希；空结果、缺项、重复项、跳过、空证据、退出码与报告矛盾、运行中修改输入均不能得到完整通过。执行有超时和输出上限，并清理子进程组。检查环境不继承模型密钥、会话 Cookie 或运行时注入变量。Python 虚拟环境调用路径保持不变，避免改变依赖解析。

完整操作方法与协议在 [evaluation/README.md](external-gate.md)。入口不依赖具体编码器；后续 Pi/VOLO 可以共用，未接入 Pi 不伪装为已完成对照。

## 验证证据

修复前，新增恢复回归有 4 项失败；修复后 5 项通过，包含合成网关驱动的真实 HTTP 应用生成与验证，而不只是检查提示词字符串。

完整测试集运行了 **94 项，全部通过、零跳过**，包括此前没有运行的四项真实 Chrome 回归。随后最终外部评分器的虚拟环境修订及新增测试，在 **17 项专项回归中全部通过**。合并覆盖 95 个不同测试；不是一次全新 95 项全量运行。原有 73 项测试没有删改。

外部评分的正反控制包括：正确 HTTP 应用接受、错误应用拒绝；只把错误应用的自测改成退出 0，不改变外部失败结果；没有场景的退出 0 也不能产生可信通过。

两次构建的上传 ZIP 完全一致，13 个文件，外部评分器/文档/开发测试不进入上传包。没有上传、没有官方运行、没有真实模型调用，也没有委派 Codex 消耗周额度。

逐项结果、源码和 ZIP 哈希见 [validation.json](../../evidence/2026-09-12-dev30-validation.json)。

## 尚未完成的边界

此 gate 不是 OS 沙箱：同用户权限进程仍可能访问外部目录；哈希也不能防止修改后恢复。真正权限隔离需要容器/不同权限域，运行地址与冻结产物的绑定目前仍由操作者保证。

这不是自动正确的评判器。真实任务测试需要独立正反例校准，完整官方测试报告适配尚未接入；没有通过提供一段固定测试代码来声称解决了需求语义问题。原有页面布局规则未继续加码，也尚未做消融。

Pi 运行适配、匹配模型条件的对照和分数提升仍未完成。下一项应是将真实任务的同一套只读验收与隔离运行器接到两个执行器上，再按预注册预算比较；不是因本地测试变绿立即继续大量提交。
