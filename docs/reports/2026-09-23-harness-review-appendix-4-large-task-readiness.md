## 3. 规模上限估算

- **输入**：12306 提示 198,166 字符，按 4.07 字符/token 约 4.9 万 token；Ctrip 约 4.3 万。修复轮带上草稿后约 8 万，二次修复约 11 万。网关对 kimi-k2.7 的上下文上限本次没有核实。
- **输出**：正文按 2.4–2.7 倍外推，约 2.7 万–3.0 万 token，偏高情形约 3.7 万。
  - 如果推理像 flash 一样不随题目变大，维持 3.8 万（最高 5.5 万），总量中值约 6.5 万–6.8 万，偏高情形约 9.2 万。
  - 要触到 131,072，推理需达到 9.4 万–10.4 万，是中题最高值的 1.7–1.9 倍。中题里没见过，但 12306 的需求文本是 Lite BookStack 的 3.5 倍，不能排除。
- **max_tokens 是否包含推理**：k2.7 没有实测。间接证据是 09-17 那次上限 12,000 的扫描里，kimi-k3 以 12,372 个 completion token 结束于 `length`，说明推理很可能算在上限内。
- **续写兜底存在，但很薄**：只能续写一次，要占用 3 次调用中的一次，而且要从头重发被截断的约 10 万字符 `app.js`。以下三种情形会直接整题退出：
  - 推理吃满上限、正文为空时抛出 `ValueError`，不在重试范围内（281–282 行）；
  - 恰好截在两个文件之间（1096–1097 行）；
  - 续写再次被截断。
- **时间**：
  - 平台对单条流有约 1,200 s 的硬切断：GLM 三次都断在 1,201 s，官方 Qwen Keep 两次断在 1,200.07 s。
  - HighSpeed 跑满 131,072 需要 615–700 s，吞吐不低于约 110 tok/s 就安全。
  - 单次大题 agent 总时长估计 12–20 分钟。
  - 整项任务的平台超时没找到文档：模拟仓库只写了 120 s 应用启动和 10 s 单测超时，须知只说有"超时上限"但没给数值。平台实际接受过 2,491 s 的 agent 阶段和 3,708 s 的整次运行（`2eef0a0f987a`），所以大概率不是第一约束。
- **探针耗时**：走查每一步都要对全部可见按钮逐个做 CDP 调用，时限只在步与步之间检查。在 12306 结果表这类有数百个按钮的页面上，单步可能超过 40 s 上限，导致修复前后结果不对称、修复被拒。这一点未实测。
- **费用**：大题一次约 9–12 元，一次正式评测（中题加大题）约 15 元。评分公式里费用只做 0.1–0.2 次方修正，不构成约束。

## 4. 大题最先撞上的瓶颈（按对合并分数的影响排序）

1. **导航入口与路由结构错误，而候选没有针对它的机制。**
   - 这是历史上最大的系统性失败族：12306 入口族占 24.7%，Ctrip 占 35%，每个样本因此级联失败 15–35 例。
   - Kimi 在中题上已有两次结构性灾难，官方 v24 那次门禁完全没看到。
   - 最小改法方向：移植 arc-optimization-loop 的路径表（进提示）和路径走查（进门禁），再加一条通用检查：逐个点击导航链接和种子记录链接，要求目标屏幕出现对应的记录名或标题。
2. **修复在大文件上被验收规则丢弃，或整文件重写把好的部分改坏。**
   - 44 个大题 run 中有 14 次修复被拒。
   - Ctrip 最近 6 次修复全被 "+ 添加返程" 否决，而测试本身也接受不带 "+" 的 `/添加返程/`。
   - 最小改法方向：
     - 移植"修掉整页故障就保留"的例外；
     - 改名判断改用渲染后的可访问名，并去掉前导符号再比较；
     - 把 `app.js` 按屏幕拆成模块，修复只重发被点名的模块。
3. **Kimi 专属的整题归零路径。**
   - 传输失败不回退；推理吃满上限时直接退出；续写只有一次；温度固定为 1.0。
   - flash 时代每 4 个大题 run 就有 1 个断过流，而 Kimi 在平台大题路径上的断流率完全没有数据。
   - 最小改法方向：
     - 大题起草的传输失败允许回退到 qwen（样本会不可比，但交付总好过 0 分）；
     - 把"length 且正文为空"改成可续写或可重试；
     - 在实验里逐次记录推理 token。
4. **卡片和门禁与大题语料错位，方向取决于正式大题怎么写。**
   - 如果沿用 Lite 写法：词汇表、词汇门、精确名门、改名否决都只认双引号。Lite BookStack 的 81 个反引号名字里有 43 个进不了词汇表，例如 `Create New Book`、`New Shelf`、`Login form`、`Book Tags`。大题上会有上百个名字没人检查，而词汇门在 Web 大题上每次都能报出 10–15 个缺失短语。
   - 如果沿用 Web 写法：被删的规则会让 Sign Out、edit/delete、依赖 GIVEN 预置数据的大批用例回退。
   - 最小改法方向：`QUOTED` 纳入反引号；把被删的 Web 规则改写成"需求没写明角色或种子时的默认做法"放回卡片。

## 5. 只剩一天时的最小实验（不上正式赛）

**第 0 步：零模型调用，约 1 小时。**
- 用 WT 的 `smoke_check` 和修复验收代码，在 `TZ=UTC`、1 CPU、2 GB 下复查三个现成产物：
  - `runs/2026-09-18-goal/r27a-12306-bundle`
  - `runs/2026-09-20-goal/r28a-12306-bundle`
  - `runs/2026-09-20-goal/ctrip-goal-bundle`（09-19 那次空白页）
- 判据：
  - 探针三次都 `executed=true`，且每次少于 30 s；
  - 除已知族外不报新问题；
  - 记下"修好整页但改动了 + 添加返程"的情形在候选规则下是否仍被否决。
- 任何一条不满足，先修再花钱。

**第 1 步：练习平台 arc-bench-web。**
- 把冻结的 v24 包（`959890c1…`）原样用 `kimi-k2.7-code-highspeed` 上传。
- 串行跑 12306 两次、Ctrip 两次，期间不跑任何本地模型调用。
