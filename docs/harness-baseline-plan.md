## G0：先使测量可信

本轮 [离线诊断](evidence/2026-09-12-harness-boundary-audit.json) 已复现基线的空检查通过、自测削弱和截断不退出整包模式。诊断成功不是 harness 修复成功；运行时代码未改。

下一步为外层评分器建立正反控制：正确实现通过，缺失真实行为失败，空检查不能代表完成，删改自测不能改变同一产物的可信评分，合法重复导航不能被通用规则误杀。故意做错的产物仅用于校准，不是竞赛提交。

固定历史产物在受控环境重放；不必每次再付费生成代码。记录产物/测试包哈希、浏览器/Node 版本、线程、超时、资源限制和初始数据。无法取得官方参数则标为近似复现。旧 trace 能验证协议和故障恢复，不能代替模型在新上下文中的真实执行来证明效果。

这些检查只证明接线，不证明解题能力。本轮未安装 Pi、未调用真实模型。

## G2：固定模型的最小配对试验

A：冻结当前 VOLO，不先为它修复后再声称是原始基线。
B：固定 Pi + 最薄竞赛适配，不移植 VOLO 全套提示词和特殊规则。
两者使用同一独立评分外壳、同一运行预算及隔离条件。

固定项目：需求与图片版本、初始工程、模型标识/参数/provider 路由、环境、测试包版本、资源上限、是否允许自测访问公开验收。核对实际发出的请求，而不只看配置名；模型有随机性，temperature=0 不等于必然一致。执行顺序交错减少时段偏差。

先用一个开发任务做一对运行，检查证据完整性。只有得到新的可解释信息，才扩展到小型增量、有状态应用、不同领域任务。Ticket 已反复调过，不再作为 holdout；改字段名也不足以证明泛化。为本轮预留没有参与调参的独立任务族，评估前冻结候选。少量运行只能形成方向性判断，不能宣布统计稳定或冠军。

若两边使用同一份冻结图片观察，标为条件化编码对照，并单独记观察成本。比较完整系统时，各自图片处理都计入总成本；不能只给一边更完整的输入。

每轮至少记录：源 revision、输入/产物/测试包/环境指纹、模型参数、真实通过率、可运行产物是否形成、可信覆盖与未验证场景、首次可验证产物时间、总墙钟时间、回包 usage 与官方费用及差异、无进展修复次数、人工介入次数。固定产物重放与重新生成分开。一个应用内的十项相关测试不算十次独立实验。

## G3：依据结果决定保留什么

B 明显优于 A：优先采用 B，不为维护自研核心而继续补丁。
B 仍有系统性失败：只增加一个被证据指向的机制，与 B 原版比较。例如验收边界或有界恢复。不要同时改变模型、模板、提示词和预算再做因果归因。
A/B 都失败：先看已知正确产物能否通过同一评分器，再区分环境、需求歧义、协议与模型能力；不能直接认定竞赛坏了，也不默认打开更多模型或多 Agent 扇出。

## 执行清单与停止门槛

任何付费试验前填写以下清单；未填写不是默认无限额：

```yaml
experiment_id: required
hypothesis: required
control_revision: required
candidate_revision: required
task_and_environment_hashes: required
model_and_request_parameters: required
allowed_test_visibility: required
run_count_cap: required
wall_time_cap_per_run: required
model_budget_per_run: required
campaign_total_budget: required
verification_reserve: required
promotion_criterion: required
stop_criterion: required
shared_account_coordinator: required
```

停止：预算/运行数达到上限；重复相同失败而没有新增信息；计费或环境结果不可信而无法作质量比较；评分器不能区分正反控制。遇到外部请求结果未知，查询原请求，不自动重复上传/启动。共享账户采用共同遵守的协调/租约；普通预检不是跨机器原子互斥。

新付费轮次只能在预定总预算内；API 余额充足不意味着开发者时间或 Codex 配额无限。
