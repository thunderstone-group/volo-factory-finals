# Removing browser self-navigation from generated applications (2026-09-14)

The official E057 run scored 9/10; its one failure,
`REQ-1.1: successfully register a new account and remain signed in`, timed out at 10,013 ms on
an idle hosted runner. The [timing measurement](registration-timing-2026-09-14.md) found no
application-side lever worth more than a tenth of that test's cost, but it did find the one
mechanism that makes a healthy application fail nondeterministically: after an awaited `fetch`,
the application assigns `window.location.href = '/'`, and that navigation races the test's next
`page.goto` or `page.reload`. Ten of 48 replays of an application that does this failed with
`net::ERR_ABORTED` or "interrupted by another navigation"; none of the 18 replays of the same
application re-rendering in place did.

This task removes that pattern at the source: the generation prompt forbids it, and verification
rejects it statically. Raw numbers are in `docs/evidence/2026-09-14-nav-race-trial.json`.

## What changed

**Generation prompts** (`volo/agent.py`). The bounded multi-route prompt and the general system
prompt now state that after a form submission or sign-out the application must not assign
`window.location` or `location.href`, call `location.assign/replace/reload`, emit
`<meta http-equiv="refresh">` or let a native form navigate. It must call `preventDefault`, render
the destination route in place, and set the URL with `history.replaceState`; in-app links route
through a click handler, `history.pushState` and a `popstate` handler. Two existing lines were
adjusted so the new rule does not contradict them: the route line now says routes are implemented
by *reading* `location.pathname`, and the rule states explicitly that a requirement to return to
`/` after submitting is satisfied by rendering `/` in place. Direct entry to `/register` or
`/login` must still serve and render that route, which the runtime already does.

**Static guard** (`volo/workspace.py`). `Workspace.self_navigation_guard` scans product source the
run authored, before dependency installation, and `verify` returns a failed result naming the file,
line and offending text. The existing bounded repair path consumes that error like any other
verification failure. The guard allows every `history.*` call and every read of `location.pathname`;
it skips `checks/`, and it skips files an existing project supplied until the agent rewrites them,
so a legacy pattern in an evolution task can never make verification unreachable.

**Unit tests** (`tests/test_self_navigation.py`). Twelve navigating forms and thirteen allowed forms
are asserted case by case, plus finding bounds, the verify-level rejection before any build step,
and the authored-file scoping. `python -m unittest discover -s tests -v` reports **169 tests, 0
failures, 11 skipped**, against 163 on main. The 11 skips are the same machine-local browser and
Docker-image cases that skip on main.

The guard reproduces the measurement's own classification exactly. Run against the seven ablation
variants, it reports three findings for each of the five that kept `location.href` and failed in 10
of 48 replays, and none for the two that re-render in place and failed in none of 18.

## Local gate

One Ticket Booking application was generated locally through the organizer gateway with
`deepseek-v4-flash`, from the retained requirement package, then replayed against the unchanged
public tests in the calibrated `host` configuration: the application in a 1 CPU / 256 MB container
behind the volo launcher, Playwright 1.57.0 and Google Chrome on macOS, workers 4,
`fullyParallel` false, 10 s test and expect timeouts, retries 0, trace and video off.

| Gate step | Result |
| --- | --- |
| Forbidden patterns in the product source | 0 |
| Replays with 10/10 | 20 of 20 |
| Suite wall, median | 5.41 s |
| Registration test, min / median / max | 591 / 634 / 720 ms |

The first generation attempt failed and did not reach the gate. Its product source was already
clean, but the model wrote `assert(locator).toBeVisible()` in its own checks; a captured
locator-ambiguity check froze those bytes, so the resulting `TypeError` could never be repaired and
the run exhausted its 450,000-token budget. The single allowed adjustment states in the
prepared-bundle prompt that `assert` is `node:assert/strict`, not Playwright `expect`. The
regenerated application completed with both requirements self-checked in 13 model calls.

## Open questions

- **The E057 stall itself is still unexplained.** This change removes a failure class that the
  bench observed at 21% per run; it is not a demonstrated cause of that specific 10 s stall, and one
  passing official run cannot separate the fix from generation variance.
- **Token count fell from 555,255 to 72,854 for the same task and model.** The official counter and
  our captured usage still disagree in the other direction on E057, so treat this drop as an
  unexplained observation rather than an efficiency result until a second run reproduces it.
- **The frozen-self-check dead end is unfixed.** When a captured locator-ambiguity check contains an
  unrelated code error, no product repair can make it pass and the run loses its budget. That trap
  is in `capture_failed_prepared_check`; it cost one local generation here and was worked around in
  the prompt, not in the harness.
- **The guard only scans files the run authored.** An evolution task that never rewrites a legacy
  file keeps whatever navigation that file performs.
