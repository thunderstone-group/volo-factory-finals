# VOLO Harness 开发蓝图

日期2026-09-17；主仓库volo-factory。目标：沿V2基线补有证据、有限次、真正进入参赛包的纠错，不重写框架。依据：harness-audit-2026-09-17.md及runs/harness-audit-20260917。

## 1. 不变边界

保留V2生成提示、低推理控制、共用编辑器/导航、原A0与历史包。模型固定deepseek-v4-flash；不恢复旧调度，不增加技能/组件库，不输入官方测试、旧失败日志、分数或练习题特例。未取得独立校准验收时verified_requirements保持空。

## 2. 目标链路与证据分层

完整需求 → 生成A0 → 确定性检查与需求诊断 → 有界补丁 → 同范围复验 → 保留候选 → 官方评分。

交付/语法、源码审查、真实浏览器、官方分数是四层不同证据。模型源码审查只产生诊断，不是业务pass；Node解析通过不是运行正确。未运行浏览器明确标browser_executed=false。

## 3. 本轮交付切片thin-source-v1

先交付不依赖bwrap、不在凭据进程执行生成应用的参赛入口。

- 复用V2/Flash低推理首次生成，原生成重试预算不变。
- 对JS/CJS/MJS及HTML内联脚本执行可信Node --check，检查manifest及本地script引用。清空NODE_OPTIONS；不执行npm脚本、不启动生成应用、不安装依赖。缺工具是environment_error。
- 一个完整需求—源码审查请求，重点登录、创建、编辑保存重读、导航、响应解码、取消/撤销与跨视图状态。问题须引用需求与实际源码；omission允许缺失功能没有源码标签，不能要求功能先存在才能诊断。禁止猜测需求未提供的ARIA或具体控件名。
- 复用三项原技能和受限补丁客户端；修复看完整需求与本次诊断，不看官方测试。所有路径、哈希、旧文本、受保护模块仍校验。
- 最多两轮，每个候选重新做同范围确定性检查；语法/结构退步拒绝。合格补丁标candidate_static_pass，只作为实验交付，不能声称行为改善。下一轮继续审查当前源码。
- 生成后诊断失败保留A0；可选运行能力缺失不让已合格基线无产物。明确语法错误未修复不能冒称交付合格。

本切片不是完整浏览器闭环。实际运行资格尚未证明的分支不进入包；由平台task验证当前新增源码反馈是否提高完整通过率。

## 4. 修复现有业务协调器

增加opt-in per_check策略，旧策略保留历史可复现性：
按项选择有来源完整性证据的product_fail；独立unknown不压制明确故障，environment_error永不当产品错误送修。全局来源/运行完整性失败仍停。
候选保护已通过项，不把明确失败变unknown当进步。有新增真实pass且已知项不退步时保留部分改善；后续模型错误/无变化/预算耗尽不丢弃已保留版本。未覆盖项仍未知。
该策略独立回归；本轮未实际执行的浏览器分支不得记已部署。

## 5. 后续运行接口

优先复用既有DockerRuntime和独立评估容器，不扩造原生沙箱。bms是开发设备，不等于平台环境；不重试被拒namespace，不加privileged，不暴露Docker socket、主目录或凭据。
运行路径优先登录/创建→保存与刷新重读→导航→取消/撤销。预期来自需求，定位来自实际界面。区分工具缺失、产品构建/启动错误、定位不确定和证据不足。

## 6. 预算与可追溯性

生成最多3次；审查最多2次；技能修复最多2轮，共享6次请求。审查/修复对话单次上限300秒、16384输出tokens，入口1790秒硬墙钟，留交付清理时间。
记录实际请求、finish_reason、usage与耗时；未知费用不置零，不把请求参数等同服务端已兑现。
保留A0、候选、最终源码、需求/包摘要、逐阶段调用数、诊断及停止原因。证据脱敏；不记录推理正文或API key。部分保留和未执行业务检查均显式。

## 7. 验收

需求/源码引用校验、遗漏功能可表达、混合unknown路由、部分改善、非法/越界补丁拒绝、模型失败保留A0、真实Node语法、内联脚本和引用、平台元数据保留、解包入口合成网关、可复现白名单打包。
合成响应不是模型质量证据；不重跑被拒socket/namespace测试。

## 8. 一轮正式任务实验

同一冻结包/Flash，先Bookstack后Keep，各一次。上传一次；每次启动前查全账号active runs，运行期间无同key本地调用，不覆盖运行中的包，不重复不确定launch。
保存回下载哈希、run ID、完整case、阶段日志、费用与榜单。旧Pro只作历史参考，不作为纯harness因果对照。
若可取回同次A0/B，则在冻结原套件追加零模型回放；取回失败如实报告，不补抽替代。两项完成后报告补丁是否采用、实际结果与退步，不凭一个样本宣布泛化。

## 9. 文件归属

oneshot/thin/：入口、语法、审查；复用v2/effort_entry/skill_repair/platform_entry。
tests_oneshot/test_thin.py及业务策略回归；scripts/package_thin.py独立冻结包，不改默认包。
runs/thin-task-round-20260917/保存实验；结束更新交接，不在未验收时合并main。

外部核对：Node官方--check仅语法解析；DeepSeek文档分别定义thinking、reasoning_effort、max_tokens与finish_reason。主办方网关以实际回执为准，不替换其Flash模型ID。
