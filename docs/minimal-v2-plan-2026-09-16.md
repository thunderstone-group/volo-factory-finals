# Minimal V2 bounded experiment

Use the existing worktree and retain V0/V1 artifacts. Provide two immutable, domain-neutral JS modules: editor/row actions and initialization/navigation. Names enter as application requirement data. Keep the model, runtime, original requirements and score suites fixed; no task-specific application template, planner call, sample repair, model switch or large component framework.

Before model calls, run real isolated-browser paths on a clearly synthetic application: open editor, save, reopen; navigate to list and open an entity. Use browser JS coverage plus actual DOM/state assertions to show the shared code executed. Then freeze a separate V2 ZIP and its hash; generate Keep and Bookstack twice each with deepseek-v4-pro (four samples, at most twelve gateway attempts, 1500 seconds per sample). Generate the entire batch before inspecting outcomes or scoring; retain failures rather than replacing samples. Run the original frozen suites and separately inspect the same real entry paths in generated apps. Generated checks do not become official scores and no offline test assertions reach the model.

Compare all results with the retained V1 Pro: Keep 6/32, 7/32, 6/32; Bookstack 8/34, 5/34, 8/34. Proceed beyond these four only when both task medians improve and the observed shared entry paths work; this turn does not automatically expand the batch. Failed shared paths direct the next change to shared integration; successful entry paths with failed business checks direct investigation to business implementation. Explicitly separate unspecified UI contracts and draft questions for the organizer locally; do not send them.

Retain current isolation: pinned existing image, no downloads/install, no external app network or host ports, original sources read-only, owned resources cleaned. No upload, official submission, push, merge or default-package change. Record code/prompt/package hashes, actual request receipts, usage unknowns, failures, cost and complete outcomes in a V2 report; update the existing development log and handoff.
