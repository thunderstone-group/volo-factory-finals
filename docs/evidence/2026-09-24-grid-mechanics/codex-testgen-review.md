# 一次性生成包接入需求生成 Playwright 测试：对抗评审

**结论：改后做。** 先把少量、可独立校准的生成测试作为故障定位器和受保护的修复入口；v0 的全量测试、自动二分归因和“三得一失”验收，尚不足以决定是否保留一次整文件修复。

评审基线是 `main` 的 `47c9fd4`、提交 2 的 Sheet 产物及已有测试原型。提交 3 和 GitHub 补齐 `E2E_*` 后的重评结果未知，不能把提交 2 的 22.5% 当作它们的分数。赛制按两题 200 条测试计分，费用进入 0.1 次方，正式环境为 1 核、2 GB、单 worker、单测试 10 秒（`docs/reference/preliminary-rules.md:42-66,82-89`；`docs/progress.md:1082-1090`）。

## 与早上判断的关系

早上的评审把全量模型测试排第五，理由是 fixture 真伪、执行时间和“本地绿灯不等于隐藏通过”（`docs/evidence/2026-09-24-opening-day/codex-direction-review.md:1-19`）。新证据改变了**诊断价值**：场景自检在 Sheet/GitHub 仅覆盖 0/48、1/64，修复根本不启动；原型在 Sheet 提交 2 上报出了标签名污染、行内编辑缺失、下拉框、粘贴与绝对引用等真实缺陷（`docs/progress.md:1025-1029,1066-1074`）。这支持用独立浏览器路径打开修复入口。新证据没有证明**验收可靠性或净得分**：原型只覆盖 Sheet 的 48 个场景，隐藏测试是 100 条；生成 fixture 自身出错，且不少本地通过的需求仍有隐藏超时。

## 最高风险与最便宜证伪实验

### P0：共享 fixture 错误被批量当成应用错误

原型提示词强制“应用从空库启动，所有前置状态经 UI 创建”，而 Sheet 需求明确有预配置工作簿和由测试放入的浏览器剪贴板（`testgen/testgen_proto.py:32-45`，路径前缀为 `docs/evidence/2026-09-24-opening-day/`；正式需求 `requirements/hackathon--sheet/requirements.yaml:855-863`，路径前缀为 `~/projects/arcbench-campaign/evidence/2026-09-24-hackathon/`）。它可能测试到另一个创建路径，或把无法自行建立的 GIVEN 状态误判成产品失败。原型原始 JSON 的 20 个失败里，逐条解析实际有 **14** 个 `ReferenceError: page is not defined`；README 写 12，不能用该概数做门限（`testgen/suite-on-sub2-sheet.json:2331-2337`；`testgen/README.md:10-14`）。`node --check` 只能排除语法错误，排不掉这类运行时作用域错误。手修后的 `chooseOption` 才把这些失败暴露为可诊断的下拉框问题（`testgen/sheet-tests/fixtures.cjs:153-172`；`testgen/suite-on-sub2-sheet-req5-fixed.json:771-777`）。

**本地证伪**：只读解析现成的两份 suite JSON，按 stack 的首个本地源帧聚类，比较修 fixture 前后的失败集合；再对所有测试静态核对每个 GIVEN 的状态来源为“需求明确种子 / 测试经 UI 创建 / 本测试刚输入”。**写死判据**：任一共享 helper 的相同异常影响至少 2 条测试，整组标 `test-error` 并退出修复；任一 GIVEN 无可证明来源，也不计得失。现有 14 条已否决 v0 的逐条错误分类。`TypeError` 只在测试/fixture 栈顶且浏览器没有对应 page error 时归 `test-error`；页面脚本抛出的同名异常须由浏览器证据归 `app-fail`。名字“在需求某处逐字出现”只是必要线索，须匹配该步骤的角色、作用域、前置状态及断言来源；没有证据时归 `unknown`。

### P0：本地假通过会护住错误路径，也会奖励错修

提交 2 的 Sheet 原型为 28/48 通过、20/48 失败，用时 57.5 秒（`testgen/suite-on-sub2-sheet.json:2331-2337`）；按需求编号把本地通过与正式 `run-1d84ee5aa3d4.json` 的 58 个失败交叉，**至少 23 条本地通过测试所在的需求编号仍有隐藏失败**，例如 `REQ-2-2-1` 的两条本地通过而隐藏仍挂 3 条。编号重合不证明同一场景失败，但足以否决把本地通过条数当成隐藏通过的代理。路径差异有具体机制：原型 `enterCell()` 经 “Formula bar” 输入，而需求还要求直接在网格输入、双击显示 “Edit <cell coordinate>”（`testgen/sheet-tests/fixtures.cjs:88-111`；Sheet 需求 `requirements.yaml:375,403-420`）。正式 Sheet 的失败只有 10 秒超时，不能由此推断隐藏测试卡在何步（`docs/progress.md:1066-1070`）。

**本地证伪**：冻结提交 2 bundle，先按需求编号交叉现有 48 条结果与正式失败名；再在该 bundle 上用现有 `fixtures.cjs` 的 `enterCell`、`inlineEdit` 和剪贴板 helper，各走需求明列的同一状态的两条路径，测试文件与应用都不改。**写死判据**：只要出现一条本地通过而同编号隐藏失败，就不许用生成测试通过率预测得分；只要同一需求两条合法路径一过一挂，就不许把其中一条绿灯作为该需求的修复保留条件。现有交叉已触发第一项。更严格的验收应为“失败路径由红转绿，已校准且冻结的不同路径零倒退”，并将未测路径记为未知。

### P1：整份 `app.js` 重发，测试抽样与计数会放过倒退

提交 2 Sheet 的 `app.js` 解压后为 71,044 字节；现有修复写入完整文件块，再重跑 `assess()`、按测试 ID 算 `gained/lost`，允许 3 个新通过抵 1 个原通过失败（`oneshot/main.py:1845-1922,1973-2015`）。它还只拦截**新出现的静态门禁类别**，同一类别内新增问题不会因该检查单独拒绝（`oneshot/main.py:1856-1860`）。旧大题 12306 的实测是 7 次整文件修复仅 1 次保留，另外 6 次改坏原有场景或未修成；每轮 0.32–0.47 元、4–9 分钟（`docs/progress.md:998-1009`）。这不是两道正式题的修复成功率，但足以要求先做固定初稿试验。

**本地证伪**：不调用模型，用旧 12306 的七轮保存报告重算“按条数三得一失”与“按 ATOMIC 编号、不同交互路径零倒退”两种裁决，并在提交 2 Sheet 的冻结 bundle 上先列出每个绿色测试覆盖的编号与路径。**写死判据**：若既有七轮中至少 4 轮被拒，或存在一个旧绿色 ATOMIC 被接受的修改弄红，否决“整文件重发 + 原 judge 直接接入”。已记录的 6/7 被拒触发前半项；正式题仍需一次固定初稿、固定测试文件的离线受控修复，证明完整交付、旧绿色路径零倒退及至少一个真实红色路径修好，才允许扩大。

## 对 v0 的具体修改

1. **先做小批量测试，并冻结测试工件。** 从明确的失败家族挑 2–4 个 ATOMIC；每条测试存需求哈希、引用的原句、GIVEN 来源、操作路径、断言来源和测试源码哈希。先让 fixture 在冻结产物上独立跑通；编译失败、共享 helper 错误、浏览器/服务启动失败、超时未到达断言均为 `test-error` 或 `unknown`，不得进修复，也不能算“修复后丢失”。测试自身不能随修复改写。GitHub 种子/`E2E_*` 的对应关系在重评前保留未知，不能强造注册前缀或预埋值。
2. **隔离每轮。** 同一轮可在一个后端进程、一个 worker 上顺序跑，按测试新建浏览器 context；每次比较必须从同一冻结应用/种子快照重新启动后端。否则共享服务器状态、随机名、测试顺序及 fixture 清理能改变结果。先跑受影响路径和最少两个不同家族的绿色护栏；完整 suite 只在小批量试验通过后作为诊断回归。`@playwright/test` 1.57.0 在指定镜像里已有，先检测可用性，再用缓存前缀兜底，安装失败归工具不可用（`docs/reference/preliminary-rules.md:63-66`）。
3. **修改接受规则。** `app-fail` 才能触发修复；因同一 fixture 造成的多个失败只算一个阻塞故障，不能给多倍收益。按 ATOMIC 编号报告覆盖，但每个编号只在至少一条已校准失败路径转绿时记一次收益；已经校准的不同路径和已有绿色 ATOMIC **零倒退**，交付、浏览器 fatal、精确可访问名及静态问题也零新增。没有已校准绿色护栏则只做诊断，不自动保留修复。旧“三得一失”仅适用于已校准的旧场景，不能混算 48 个模型测试与 100 条隐藏测试。现有修复的回滚结构可复用，报告与裁决必须分开；仍保留 3 元/题和拒绝次数上限（`oneshot/main.py:42-48,1938-2025`）。
4. **先保留旧场景解析作诊断，按需求哈希关闭无效翻译。** 两题这版 0/48、1/64，花了 0.22/0.25 元；可以对这两个需求哈希跳过再调用，把一般任务的场景自检保留。删除整个机制会影响其他需求，节约不到生成测试的成本（`docs/progress.md:1025-1029`）。并行生成测试需独立预算/trace；fixture 完成后 spec 才能开始，模型并发与初稿同走网关，所以“零墙钟增加”必须实测，不能承诺。

## 成本、时间与优先级

原型五个 spec 调用耗 2.41 元，**不含新生成 fixture 的未知费用**；每个 spec 目前都带整份需求文本，且 fixture 后才按顶层目录并发（`testgen/README.md:3-9`；`testgen/testgen_proto.py:104-148`）。最便宜的降本试验是只传目标 ATOMIC 子树、依赖闭包、相关 `data` 与共同 UI 契约，按失败家族生成 2–4 个测试；不要拆成 71 次调用。`reasoning_effort=low` 可以与原设置对同一冻结小批量做配对，比较可解析率、fixture 错误、两条路径的判别力、费用及最长调用时间；任一新增假 app-fail 或少报一个已知真故障就不采用。推理 token 很多，但低推理是否省钱而不损质量尚无样本（`docs/progress.md:1076-1078`）。

按提交 2 的 2.10 元基线、总费 12/15/18 元计算，想不降 S，合计通过率分别至少约 **26.36/26.90/27.35%**，即 200 条里至少 **53/54/55** 条，对 45 条基线需要净增 **8/9/10** 条；这是公式推导，不是收益预测（`docs/reference/preliminary-rules.md:42-59`）。提交 3 或重评改变基线时必须重算。一次原型 48 条在较快的本机上 57.5 秒，11 条 REQ-5 重跑用 46.6 秒；不能外推到 1 核正式环境（`testgen/suite-on-sub2-sheet.json:2331-2337`；`testgen/suite-on-sub2-sheet-req5-fixed.json:771-777`）。若每条都耗满正式 10 秒，48/64 条单轮约 8/10.7 分钟；初稿加 2–3 次修复需要 3–4 轮，两题测试时间上界的量级为 **56–75 分钟**，另有启动、模型、安装和重检。以前大题一次自检 262–302 秒、单轮修复 4–9 分钟（`docs/progress.md:998-1009`）。先在 1 核、2 GB 限额下测小批量；全量方案若单题首轮超过 10 分钟或一轮修复加复测超过 15 分钟，就停在诊断层。

## 同名控件门禁与只选一件事

**值得做窄版真实浏览器门禁，优先于全量生成测试，但暂不让它泛化触发修复。** 提交 2 GitHub 有页头/正文同名 “Sign in” 严格模式失败（`docs/progress.md:1059-1067`）；当前静态门禁只当提示，真实浏览器探针已有限路由/点击遍历，可在该层加 `getByRole(role,{name,exact:true})` 的可见匹配数观察（`oneshot/main.py:1708-1735,1938-1958`；`oneshot/semantic_probe.cjs:238-283`）。按**角色＋精确名＋测试可能使用的作用域**计数，弹窗打开时重测；重复行按钮、合法同名项、不同页面、不同角色不应报错。仅当需求要求无作用域的唯一入口、同一状态两次稳定复现且确实使精确 locator strict 失败时，才允许它单独触发**一次窄修复**，修复后复测并保护其它入口。运行时自动去重同 `href` 的链接会删掉布局中的可用入口，还解决不了按钮、标签或不同 href 的重名，不建议作为通用脚手架行为。PR #67 已改命名规则与组合框，提交 3 结果未读前，不能把这道门禁的预计得分算在它之外（`docs/progress.md:1072-1080`）。

**如果只能先做一件拿分：先攻 Sheet 的外部剪贴板粘贴短路径，并用冻结产物校准一条测试后做定向修复。** 提交 2 的 `REQ-3-1-2` 隐藏 5 条全挂，`REQ-3-2-1` 还挂 3/4；正式需求明确 Ctrl+V 使用浏览器外部剪贴板（Sheet 需求 `requirements.yaml:403-420,859-861`）。冻结 bundle 的 `pasteClipboard()` 在内部 `clipboard` 为空时直接返回，键盘监听又阻止默认 Ctrl+V，因而外部文本无法到达网格（`bundle-1d84ee5aa3d4.zip::template/frontend/public/app.js:781-800,1550-1558`）。这是可定位的通用交互缺陷，比等 93 条 GitHub fixture 重评或先生成 112 条测试更可控；修复须由模型按当次需求生成或由通用能力引导，不能把 Sheet 业务代码预置进包。用外部 `navigator.clipboard.writeText` → Ctrl+V → 六格/范围外值 → 刷新、以及右键 Paste 两条路径校准；两次稳定复现旧产物失败、新产物两条通过且原绿色路径零倒退，才值得一次正式提交验证实际净增分。该本地试验不证明隐藏测试会通过。

本次仅审阅本地代码、需求、bundle 列表及现有 JSON；没有调用模型、运行官方评测或改动包代码。
